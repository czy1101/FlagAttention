## Code findings
- Forward `chunk_fwd_h.use_parallel_state` already admits FP16, but only when
  `K == 64 and V == 64`; BF16 is unrestricted (chunk_h.py ~L1150).
- Backward `chunk_bwd_dh.use_parallel_state` (~L1385) required
  `q/k/do.dtype == torch.bfloat16`, so the FP16 backward parallel state path was
  unreachable, including for the T512 FP16 case that PR #42 adds.
- Extra common gates: PARALLEL_STATE_ENABLED, PARALLEL_BWD_STATE_ENABLED (default
  on), BS==BT==64, no cu_seqlens, HQ==H, not state_v_first, g/g_gamma/gv None,
  gk not None.

## Candidate change (minimal)
`src/flag_attn/runtime/backend/_enflame/FLA/chunk_h.py`, `chunk_bwd_dh` only:
replace the three hard BF16 dtype checks with the forward path's exact rule

    (k.dtype == torch.bfloat16) or (k.dtype == torch.float16 and K == 64 and V == 64)
    and q.dtype == k.dtype and do.dtype == k.dtype

BF16 keeps the identical original predicate (BF16 -> true, same as before).
FP16 is admitted only at K=V=64. No other gate changed; forward path untouched.
